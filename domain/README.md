# Domain Model Bindings (`domain`)

## Overview

This package loads Cognate Workbench's authoritative Interaction Domain Model (IDM) from the framework's `.sea` source and binds the app's executable cognitive capabilities to it. Per the decision recorded in the module header (`domain/index.ts` lines 1-8), `domain/` does NOT copy or symlink the `.sea` source: it re-exports it in place, reading `APP/.sea/interaction/interaction-model.sea` at startup via `loadSemanticProjection` from the `@godspeedai/cognate-domainforge` npm dependency. That `.sea` file remains the single source of truth for the IDM; `domain/index.ts` is the one place in the codebase that knows its path.

The module exports one loader (`loadDomain`) plus a set of explicit capability-anchor tables and per-tranche `bind*` functions. Every binding is declared explicitly against a named IDM entity — nothing is inferred — and each binder validates its expected contract count before returning. The project model (`.sea/interaction/interaction-model.sea`) is authoritative; the semantic namespace `"deepseek-harness.interaction"` is preserved for compatibility with persisted evidence.

This directory has no code subdirectories. Related non-binding decision helpers live outside this package in `src/domain/` (e.g. `approvalGate.ts`, `planGate.ts`); this package intentionally does not bind `ApprovalGate` or `PlanMode` as `CapabilityContract`s (see Invariants).

## Invariants

- The IDM is read in place from `../.sea/interaction/interaction-model.sea` relative to this module (`INTERACTION_MODEL_URL`, `[domain/index.ts:INTERACTION_MODEL_URL]`); it must never be copied or symlinked into `domain/` — the `.sea` file stays the single source of truth and this module is the one place that knows its path.
- The semantic namespace is hard-coded to `"deepseek-harness.interaction"` (`[domain/index.ts:loadDomain]`); it must not change, because persisted evidence references those semantic ids.
- Semantic ids are always `${namespace}::${EntityName}` (`[domain/index.ts:Domain]`); binder call sites must go through `domain.semanticId`, never construct ids inline.
- `loadDomain` fails fast: any `.sea` parse error throws `domain: failed to parse interaction-model.sea: ...` (`[domain/index.ts:loadDomain]`).
- Every binder asserts its expected contract count and throws on mismatch: cognitive 20 (`[domain/index.ts:bindCognitiveCapabilities]`), tranche 5 5 (`[domain/index.ts:bindTranche5]`), tranche 7 5 (`[domain/index.ts:bindTranche7]`), tranche 9 1 (`[domain/index.ts:bindTranche9]`), tranche 10 1 (`[domain/index.ts:bindTranche10]`), usage 2 11 (`[domain/index.ts:bindUsage2]`), usage 3 2 (`[domain/index.ts:bindUsage3]`), execution worlds 7 (`[domain/index.ts:bindExecutionWorlds]`), workbench `contracts.length === bindings.length` (`[domain/index.ts:bindWorkbench]`), tranche 11 `contracts.length === bindings.length` (`[domain/index.ts:bindTranche11]`), schedule 4 (`[domain/index.ts:bindScheduleCapabilities]`), runtime execution 1 (`[domain/index.ts:bindRuntimeExecution]`), T8 identity `contracts.length === bindings.length` (`[domain/index.ts:bindT8Identity]`); governance, settlement, ambiguous-invocation, expert, RED journey, and checkout binders assert `contracts.length === bindings.length` (`[domain/index.ts:bindGovernanceCapabilities]`, `[domain/index.ts:bindSettlementCapabilities]`, `[domain/index.ts:bindAmbiguousCapabilities]`, `[domain/index.ts:bindExpertCapabilities]`, `[domain/index.ts:bindRedJourneys]`, `[domain/index.ts:bindCheckoutCapabilities]`).
- `bindCognitiveCapabilities`, `bindRedJourneys`, and `bindCheckoutCapabilities` additionally throw if any returned contract has no `SemanticRef` (`[domain/index.ts:bindCognitiveCapabilities]`, `[domain/index.ts:bindRedJourneys]`, `[domain/index.ts:bindCheckoutCapabilities]`).
- Only capabilities this app actually publishes are bound — no speculative bindings (idm-to-cognate.md traceability rule #1; see `tranche5Bindings` doc comment, `[domain/index.ts:tranche5Bindings]`). Pure state reads (e.g. a world list) are not capabilities and are not bound (`[domain/index.ts:executionWorldBindings]` doc comment).
- `ApprovalGate` is deliberately left unbound — it is realized as a pure decision function (`src/domain/approvalGate.ts`) plus a `ctx.waitFor` continuation inside `agent.coding`, not a `CapabilityContract` (`[domain/index.ts:tranche7Bindings]` doc comment). `PlanMode` follows the same shape: app events folded by the `plans` projection, only `plan.state` is bound (`[domain/index.ts:tranche9Bindings]` doc comment).
- All bound capabilities carry `version: "1.0.0"` in every anchor table and binder (`[domain/index.ts:cognitiveCapabilityBindings]` and all tranche/usage/anchor binders).
- `TaskCheckoutRecord` and `TaskBindingRecord` are durable record types in the model, never binding anchors; checkout capabilities anchor on the `Task` entity exactly as `task.move` does (`[domain/index.ts:CHECKOUT_CAPABILITY_ANCHORS]` doc comment).

## Side Effects

- Disk read at startup: `loadDomain` reads `../.sea/interaction/interaction-model.sea` via `readFile` from `node:fs/promises` (`[domain/index.ts:loadDomain]`).
- Console output: `loadDomain` logs `[domain] loaded <N> semantic objects (digest <digest>) from <path>` to stdout via `console.log` (`[domain/index.ts:loadDomain]`).
- Process-fatal failure on invalid model: `loadDomain` and every `bind*` function throw on parse or count/`SemanticRef` mismatch, failing the startup path that calls them (fail-fast contract, `[domain/index.ts:loadDomain]` and the binder count checks cited under Invariants).
- No database writes, network calls, or locks originate from this module; the `bind*` functions are pure transformations over the parsed `SemanticProjection` returned by `loadSemanticProjection` (`[domain/index.ts:bindCapabilities]` call sites, all binders).

# src-tauri — Cognate Workbench desktop shell

Tauri 2 shell that manages the Cognate backend process and hosts its UI in a native
window. The Rust side owns: backend spawn/reuse, readiness, shutdown, native menus,
zoom, window state, single-instance behavior, and a startup-failure error window.

## How the backend is managed

- Dev (`bun run tauri:dev`): the shell spawns `bun src/cli.ts start` from the checkout
  root with `COGNATE_NO_WINDOW=1` and a `PORT` it picked by binding `127.0.0.1:0`.
- Release: the shell spawns the Bun-compiled sidecar placed next to the executable
  (`cognate-workbench-<rust-triple>`, staged by `scripts/tauri-sidecar.ts`) with the
  same env plus `COGNATE_RESOURCE_DIR` pointing at the bundled
  `cognate-workbench/` resources (browser assets, `.sea` model, bundled pg0).
- Reuse: before spawning, the shell reads `<data home>/server.lock` and, if that
  process is alive and `/health` responds `ok:true`, attaches a window to it instead.
- Readiness: the shell polls `/health` until `ok:true` — a first boot (no `database/` in
  the data home; the bundled database initializes) gets a 180 s budget, a steady boot
  60 s. Readiness logs the measured time against the budget. A timed-out backend is
  asked to stop cleanly (the same SIGTERM + 60 s database-stop grace as shutdown —
  SIGKILLing it mid-initdb would orphan pg0) and the error surface carries the sidecar's
  own stderr tail.
- Shutdown: on exit the spawned child gets SIGTERM (60 s grace, then SIGKILL; a 90 s
  wedge failsafe covers a hung event loop after an external SIGTERM/SIGINT). The grace
  exists because the sidecar's clean stop covers app teardown AND the bundled database's
  own stop — a shorter window SIGKILLed it mid-cleanup and orphaned pg0 (observed, fixed
  in `96f7fb0` at 30 s; the E1 CI smoke found 30 s expiring on cold, loaded machines and
  the timers were raised together in `f9c23fe`'s aftermath). On Windows there is no
  portable SIGTERM for a
  detached child, so the process is terminated directly — the same clean-stop gap the
  standalone package documents for Windows; the bundled database stop on Windows
  remains unverified.
- Watchdog: every 5 s the shell probes `/health`. A spawned backend that dies opens an
  error window with the exit status and the log path (`<data home>/desktop-shell.log`,
  rotated at 5 MB, one `.1` retained); two consecutive failed probes — a hung spawned
  backend or a reused owner that died — open a recovery window that names what
  happened, who owns the lock, and the relaunch move. Probe liveness reads only
  `ok`, so a `/health` projection hiccup never flaps the watchdog.
- Close guard: closing a shell-owned backend's window is confirmed unless `/health`
  reports healthy with `runsInFlight` and `pendingApprovals` both present and zero —
  the server's own counts, never the page's; missing counts decide fail-closed. A
  reused backend's window just closes (its owner manages its lifetime).

## Security posture

- The main window loads `http://127.0.0.1:<port>/` — a **remote** context for Tauri.
- **No capability files are shipped.** The web content therefore has no Tauri IPC:
  no filesystem, shell, dialog, or any other privileged API is reachable from the UI,
  and nothing is reachable from any content the app later navigates to.
- Native menus, zoom, and window state work purely Rust-side; no JS bridge exists.
- The bundled fallback/error page (`dist/`) is local content, also with no granted
  capabilities, and its CSP is set in `tauri.conf.json`.
- The backend itself keeps its own loopback-only, Host/Origin-checked server
  (`src/server.ts`); the shell adds no new network surface.

## Layout

- `src/lib.rs` — app builder, menus, zoom.
- `src/backend.rs` — backend lifecycle (spawn/reuse/health/watchdog/shutdown).
- `dist/index.html` — startup-failure window content (`frontendDist`).
- `resources/cognate-workbench/` — release-only, staged by `scripts/tauri-sidecar.ts`
  (gitignored): the same tree the standalone package puts under
  `share/cognate-workbench/`.
- `binaries/cognate-workbench-<triple>` — release-only sidecar (gitignored).
- `icons/` — generated by `bun tauri icon assets/icons/cognate-workbench-256.png`.

## Package identity

The desktop shell is packaged as **`cognate-workbench-shell`** (`productName` +
`mainBinaryName` in `tauri.conf.json`), distinct from the CLI's `cognate-workbench`
package so both can install side by side — the B5 smoke run proves the two packages
have no overlapping file paths. The window title is unchanged (the builder sets it).
The bundle version comes from `package.json` (the repo's single version source) via
`src-tauri/tauri.conf.override.json`, regenerated by `scripts/tauri-sidecar.ts` and
passed with `--config` in `tauri:build` and CI. `appimage` is not a bundle target
(linuxdeploy fails FUSE-less; see `docs/known-gaps.md`).

## Commands

- `bun run tauri:dev` — run the shell against the checkout (uses `.data` home).
- `bun run tauri:build` — stage sidecar + resources, then `tauri build --config
  src-tauri/tauri.conf.override.json`.
- `cargo test` — shell unit tests (backend helpers).

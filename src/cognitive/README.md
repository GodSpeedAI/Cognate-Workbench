# Cognitive (Cases, Worlds, Mediation & Semantic Surfaces)

## Overview
Pure, event-derived cognitive semantics shared by the case console and the workbench. A
`CaseProjection` is folded on every call from durable case/world events — no store and no
authority of its own. World identity is the SHA-256 of a canonical consequential manifest
(`worldHash`); criteria are deep-frozen objects bound to their hash; candidate search never
mutates the settled world; and the mediation host orders mediators by trust tier, with the
Sentinel restoring trusted decisions when lower-trust mediation weakens them. Presentation
travels through the closed `Surface` grammar, never raw JSX/HTML. Nothing in this directory
writes durable state except where a mediator/caller explicitly hands it an emit or store
callback; the domain-model counterpart of these semantics lives in
`.sea/interaction/interaction-model.sea` (loaded in place by `domain/index.ts`, not copied here).

## Invariants
- `worldHash = SHA-256(canonical consequential manifest)`: lineage metadata (origin case/run, parent, status, timestamps) rides on events and never enters the hash, so a promoted candidate keeps its `worldHash` (`src/cognitive/world.ts` module header, `src/cognitive/world.ts:worldHash`).
- A candidate never replaces an existing world record: identical content keeps its first identity; only a `world.settled` on a `candidate` moves `settledHead` (`src/cognitive/world.ts:foldLineage`).
- Settlement gate: a candidate may become settled only if it exists, is not rejected, descends from `settledHead`, the authority is human, evidence refs are non-empty, and `settlementReachable` holds (`src/cognitive/world.ts:checkPromotion`).
- `executor != evaluator authority`: a frozen criterion is deep-frozen and bound to its hash; a revision is a new criterion with a new hash and requires human authority (`src/cognitive/criterion.ts:freezeCriterion`, `src/cognitive/criterion.ts:reviseCriterion`).
- Check results count only under the matching `criterionHash`; green does not imply settlement while `unobserved` consequences remain (`src/cognitive/criterion.ts:observe`).
- Reality is only recorded system facts; narrative events (assistant text, plans) are absent from `REALITY_SOURCES` on purpose (`src/cognitive/case.ts:REALITY_SOURCES`).
- Experiment rounds are immutable facts; the search never mutates the settled world and never settles; a round's result is decided against the frozen criterion's score, so changing the criterion starts a different comparison (`src/cognitive/experiment.ts` module header, `src/cognitive/experiment.ts:judgeRound`).
- Method review authority chain: observe != recommend != decide != settle; only an explicit human decision (`authority.kind === "user"`) moves `activeMethodHash`, and `recommendFromRounds` is pure by construction (`src/cognitive/method.ts:acceptMethod`, `src/cognitive/method.ts:recommendFromRounds`).
- The outer observer may never write protected targets: `AGENTS.md`, `.agents/specs/`, anything matching `criterion` or `active-method` (`src/cognitive/method.ts:observerMayWrite`, `src/cognitive/method.ts:PROTECTED`).
- Mediation chains are ordered by trust tier, then registration sequence — never by timing; a tier is fixed at registration and `registrar(maxAuthority)` refuses more-trusted tiers (`src/cognitive/mediation.ts:createMediationHost`, `src/cognitive/mediation.ts:registrar`); `next.trusted` re-enters against a shadow core only and recursion raises `TrustedSubchainRecursion` (`src/cognitive/mediation.ts:Next`, `src/cognitive/mediation.ts:dispatch` internal).
- The event origin is the initiating actor and cannot be rewritten by mediation (`src/cognitive/mediation.ts:dispatch` internal `next`).
- Sentinel intervenes only for declared protected invariants and only restores the trusted decision; approval itself is still decided by the trusted core/continuation path, and every intervention is a durable `Finding` via `config.emit` (`src/cognitive/sentinel.ts:sentinel`).
- A non-user origin cannot synthesize approval (`continuation.resume` with `approved: true`); mediators may invoke only declared capabilities; protected evidence targets refuse non-governance writes; irreversible operations require a preflight id (`src/cognitive/sentinel.ts:sentinel`).
- Focus context is ephemeral by construction: in-memory only, never written to an event, lost on reload; focus never confers authority (`src/cognitive/focus.ts:createFocusStore`, `src/cognitive/focus.ts` module header).
- `planInvoke` never executes a mutating action: it returns a capability request for the Cognate capability path (policy -> mediation -> continuation), and unknown or not-currently-offered actions are refused (`src/cognitive/focus.ts:planInvoke`).
- Surfaces are data in a closed grammar: `validateSurface` rejects unknown block types, unknown keys and non-string leaves, so representation stays a governed capability rather than an injection channel; `timeline` entries must be in consequential order (`src/cognitive/surface.ts:validateSurface`, `src/cognitive/surface.ts:block` internal).
- LiveVerify stays quiet on healthy transitions: only a change of verdict surfaces, and the first observation being healthy is silent (`src/cognitive/liveverify.ts:execute` internal).
- Preflight presentation never asserts authority: it attaches the Surface only when the trusted chain already set `approvalRequired === true`; waiving by lower-trust mods is caught by Sentinel's trusted subchain (`src/cognitive/preflight.ts:riskPreflight`).

## Side Effects
- Directory-wide, modules are pure folds/derivations; durable state is written only through callbacks supplied by callers: `SentinelConfig.emit` (findings), `EffectsLike.register` (disposer registration, e.g. a Cognate `FiberContext.effects`), and `LiveVerifyOptions.run`/`onVerdict` (`src/cognitive/sentinel.ts:SentinelConfig`, `src/cognitive/mediation.ts:EffectsLike`, `src/cognitive/liveverify.ts:LiveVerifyOptions`).
- `createFocusStore` mutates only process memory and notifies subscribers; no durable write path exists (`src/cognitive/focus.ts:createFocusStore`).
- `liveVerify` schedules real timers (`setTimeout`/`clearTimeout`) unless injectable `opts.timers` are supplied for deterministic tests, and registers a timer-disposal cleanup with the provided effects (`src/cognitive/liveverify.ts:liveVerify`).
- `riskPreflight` calls the injected `derive(command, targets)` to compute impact, but performs no I/O itself (`src/cognitive/preflight.ts:riskPreflight`).
- The tokenizer-free hashing in `canonical.ts` uses `node:crypto` `createHash("sha256")` — CPU-only, no I/O (`src/cognitive/canonical.ts:sha256`).

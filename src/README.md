# src (Root Application Package)

## Overview

The Cognate Workbench application source. `src/server.ts` is the app entry point: a
single Bun process that composes the Cognate kernel runtime (`createRuntime`), a
Connect RuntimeService handled in-process, the bundled React UI, and the boot-time
wiring of every agent, capability component, projection, and background service.
`src/store.ts` is the PostgreSQL/pg0 persistence default (schema derived
deterministically from the data path; `COGNATE_POSTGRES_URL` selects an externally
managed PostgreSQL, otherwise the pg0-managed local instance). The authoritative
interaction model stays in `.sea/interaction/interaction-model.sea` and is loaded
in place by `src/domain/index.ts` (`loadDomain`), never copied into code.

The root directory also holds the shared, deliberately React-free vocabulary and
pure presentation/decision helpers the UI and capability layers both import:
settings inventory, keyboard shortcuts, steering queue, sidebar grouping, tool-run
grouping/labels, approval summaries, review diffs, paste attachments, plugin
lifecycle logic, model-catalog discovery, config-file export, work-details modes,
secret storage, and the execution-posture guard. The root itself mounts no UI; the
shell lives in [./ui/README.md](./ui/README.md).

## Interface

### Subdirectory contracts

- [agents](./agents/README.md) — durable Cognate agent run bodies (`agent.coding`, `agent.config`, `agent.cognitive`, `agent.expert`); run bodies only emit and wait, all I/O lives in capability handlers.
- [auth](./auth/README.md) — durable identity and revocable session ledger (`auth:identity:v1`); the bearer token is never trusted as identity.
- [capabilities](./capabilities/README.md) — the app's Cognate `Component` definitions; every capability contract mount, from client-invoked mutations through `tool.*` to operator-only surfaces.
- [cognitive](./cognitive/README.md) — pure, event-derived cognitive semantics (cases, worlds, criteria, affordances, mediation, Sentinel, surfaces, focus).
- [components](./components/README.md) — kernel wiring: the `model.generate` provider component, the hot-swapping `ProviderRegistry`, and the plugin catalog `PluginRegistry`.
- [domain](./domain/README.md) — pure decision functions (`approvalGate.ts`, `planGate.ts`), deliberately NOT IDM CapabilityContracts; `domain/index.ts` loads the `.sea` model in place and exposes the bind helpers server.ts calls.
- [experts](./experts/README.md) — native Expert & Team registry (`experts:registry`), completion bridge, admission keys, billing ledger, and the governed runtime service wrapper.
- [projections](./projections/README.md) — the public read-model projections: one pure event-fold per file, tenant-prefixed rows, rebuildable.
- [schedules](./schedules/README.md) — durable schedule registry (`schedules:registry`), serialized mutation service, and the durable-intent `ScheduleEvaluator`.
- [settlement](./settlement/README.md) — governed proof settlement: orchestrator, bubblewrap verifier launcher, RealityTrace CLI bridge, SWE_SEED proof source.
- [ui](./ui/README.md) — Bun/TSX React console shell (App, composer, approvals, settings dialogs, cognitive frame, WebMCP), with child panels under `ui/experts/` and `ui/workbench/`.
- [workbench](./workbench/README.md) — pure workbench domain core: vocabulary, event reducer, authority plane, ledger/readiness, workflows, Skill OS, automations, steering, git worktree ops.

### Direct symbols (root files)

- [server.ts:startServer] — `(options: ServerOptions) => Promise<AppServer>`; composes the runtime, mounts all capability components and public projections, seeds identity/schedules/experts, starts the evaluator/bridge/settlement/observation services, and serves on `Bun.serve` (loopback only).
- [server.ts:ServerOptions] — boot configuration: `port`, `home`, `runCapacity` (`1|2|4|8`), `runOwnership`, `extraMediators`, `expertProviderFactory`, `enableScheduleEvaluation`, `containmentConfig`, `devAuth`, `executionPosture`, `externalAuthority`, `realitytrace`, `sweSeed`.
- [server.ts:AppServer] — returned handle: `url`, `runtime` (with the governed service), `executionPosture`, `operatorSessionToken` (this boot's browser session; the session-authenticated HTTP test seam), optional `settlement` (`settleRun`/`idle`), `stop()`.
- [server.ts:LOCAL_OPERATOR] — the single durable operator caller (`actor.id "operator"`, `kind "user"`, `tenant "local"`); [server.ts:SYSTEM_CALLER] is the system caller (`actor.id "system"`).
- [server.ts:parseRunOwnershipMode] — parses `COGNATE_RUN_OWNERSHIP`; unset/empty = `"single-process"`, any other value than the two names throws.
- [server.ts:loopbackRefusal] — request gate: non-loopback `Host` → 421, non-loopback `Origin` (when present) → 403; ports are not compared.
- [server.ts:parseDevAuth] — parses `COGNATE_DEV_AUTH`; only an explicit `"1"` arms the legacy client-claimed bearer posture, anything else non-empty throws.

## Invariants

- Single-process loopback boundary: `Bun.serve` binds `127.0.0.1` only, every response carries the hardening headers (`x-content-type-options: nosniff`, `x-frame-options: DENY`, `referrer-policy: no-referrer`, COOP/CORP `same-origin`), and [server.ts:loopbackRefusal] refuses any non-loopback `Host`/`Origin` before routing (the browser entry carries the operator session token, so a DNS-rebind page must not be same-origin).
- Capability authority is an explicit allowlist: only ids in the internal `GRANTED_CAPABILITIES` are granted, and user-kind grants belong to exactly [server.ts:LOCAL_OPERATOR]; any other provisioned identity authenticates into its own tenant partition but holds no workbench capability authority (internal `buildPolicy` in [server.ts:startServer]'s composition).
- The identity, aggregate-containment, experts and schedules shared-state threads are system-owned: `thread.state.update` on them from a non-system caller is refused by the internal `buildActionPolicy`; the identity ledger's token hashes are readable only via `identity.inspect`, never a raw thread read; `agent.expert` runs start only from the system actor via authorized durable Assignments.
- The dev authenticator is opt-in and loud: [server.ts:parseDevAuth] accepts only an explicit `"1"`, and an armed posture logs a warning and ALSO accepts durable sessions so the session-tokened browser entry keeps working; the production posture resolves every request against the durable session ledger ([auth](./auth/README.md)).
- Configuration gates compose strictly in [server.ts:startServer]: SEA-Forge governance requires the `contained` execution posture (under `uncontained-local` an agent could reach the SEA-Forge socket and approve its own escalation); governed settlement (`COGNATE_REALITYTRACE_*`) requires governance; `COGNATE_PROOF_SOURCE=swe_seed` requires settlement; and governed settlement additionally requires host containment (`COGNATE_LINUX_CONTAINMENT_CONFIG`).
- The execution-posture guard lives at the registry `get`: [executionPosture.ts:postureRegistry] wraps every provider of kind `local` — the base world, cognitive directory-copy forks, and anything registered later — so no caller can route around the refusal; invalid posture env values are startup errors, never guesses ([executionPosture.ts:parseExecutionPosture]).
- Persistence selection is deterministic: a given data directory always maps to the same PostgreSQL schema ([store.ts:schemaFor]), so restarts persist while distinct directories (each test's `mkdtemp`) map to isolated schemas with no cross-test contamination; CI may set `COGNATE_POSTGRES_URL` for an externally managed instance ([store.ts:storeConfigFor]).
- Secrets are write-only from every non-server vantage point: `secrets.json` is created and chmod'd to mode 0600 ([secrets.ts:secretStore]), read only by server-side code building live providers — never by an agent `run()`, never returned to a client, never placed in an event payload or projection.
- No secret leaves the server via the config export: [configFile.ts:describeEnvironment] redacts sensitive values, and [configFile.ts:buildConfigExport] copies only the settings keys this app actually reads, so a future projection field cannot leak into the downloadable file.
- A saved provider key may only be sent to the saved provider: [modelCatalog.ts:storedKeyTarget] compares parsed URL + protocol before `model.catalog` reuses a stored key; discovery never invents a model list — failures return a specific reason ([modelCatalog.ts:parseModelIds]).
- Images are preview-only: `ModelMessage.content` is `readonly string`, so no pixel can reach a provider; [attachments.ts:attachmentsBlockSend] refuses the send while any attachment is held and [attachments.ts:attachmentLimitNotice] worded as a limitation, never a promise ([attachments.ts] module header).
- Steering is credited by id, never by text: [steerQueue.ts:markConsumed] promotes only the ids a `workbench.steer.consumed` event names; a consumed event for one id must never clear a sibling attempt ([steerQueue.ts] module header).
- Keyboard shortcuts never lie: a chord without a modifier cannot be bound ([shortcuts.ts:validateChord]), browser-reserved chords are refused ([shortcuts.ts] `RESERVED_EXACT`), and [shortcuts.ts:resolveKeypress] never fires inside a text-entry target ([shortcuts.ts:isTypingTarget]).
- Archived is not deleted: [sidebarView.ts:applyArchiveFilter] only ever hides rows (archiving is a durable per-session fact folded by the `sessions` projection); `workspace-sections` drops empty groups while `workspace-tree` keeps them so the operator can start a session there ([sidebarView.ts:groupSessions]).
- Tool grouping is capped and key-stable: a run absorbs at most [toolGroups.ts:DEFAULT_TOOL_RUN_CAP] calls before a new group opens, keeps the first call's key, and narration boundaries are emitted as their own rows ([toolGroups.ts:groupToolRuns]).
- Plugin rows are honest: only entries whose implementation kind is `settings-toggle` with real runtime behavior render a live switch ([plugins.ts:pluginViews]); core plugins are never installable ([plugins.ts:installRefusal]); the only globally toggleable plugin id is `realitytrace` ([settings.ts:TOGGLEABLE_PLUGINS]).
- Settings patches are partial and mirrored: each `settings.change*` capability writes only its own field of [settings.ts:SettingsPatch], the projection merges per key, and the spending/containment guards mirror the enforcement layer's own parsers ([settings.ts:isSpendingCeilings], [settings.ts:isContainmentQuotas]) so the capability and enforcement cannot drift.
- Observation deliveries are at-least-once and never blocking: SXR-down queues observations and retries with backoff, then poisons for reconciliation; the drain gate (durable RealityTrace plugin state) fail-closes to "queued" ([observations.ts:wireObservations]); receipts live in the DurableStore's `observations` collection, NOT the event log, so no projection folds them ([observations.ts] module header).
- The pure root modules contain no I/O: `approvalSummary.ts`, `attachments.ts`, `configFile.ts`, `modelCatalog.ts`, `plugins.ts`, `reviewPatch.ts`, `shortcuts.ts`, `sidebarView.ts`, `settings.ts`, `steerQueue.ts`, `toolGroups.ts`, and `workDetails.ts` are React-free, client-free, DOM-free pure functions/constants by design (each file's header); all I/O is concentrated in `server.ts`, `store.ts` (selection only), `secrets.ts`, and `observations.ts`.

## Side Effects

- [server.ts:startServer] — process and filesystem: `mkdir` of the home dir and `.generated/`, writes and bundles `.generated/entry.tsx` (embedding the boot session token) with `Bun.build`, concatenates `ui/app.css` plus the eight workbench cockpit sheets and `experts.css` into `/app.css`, reads `COGNATE_LINUX_CONTAINMENT_CONFIG` JSON.
- [server.ts:startServer] — network: `Bun.serve` on `127.0.0.1` (port from `options.port` or `PORT`, default 3180) serving `/health`, the Connect RuntimeService paths `/cognate.v1.RuntimeService/*` (with security headers added), `/app.js`, `/astryx.css`, `/theme.css`, `/app.css`, and `/` (index HTML with a strict CSP); the optional Google Fonts stylesheet loads from the browser (preconnect + dynamic link, never blocking bootstrap).
- [server.ts:startServer] — durable runtime state: `createRuntime` with the store from [store.ts:storeConfigFor], four agents, 30 mounted capability components plus observation/settlement wiring, and 17 public projections; boot hygiene seeds the operator identity ([auth](./auth/README.md) `ensureIdentity`), ages expired sessions, supersedes the previous boot's browser sessions, issues this boot's operator session, reconciles containment slots and billing reservations, restores durable SSH/WSL worlds, re-swaps the last-configured model provider from the `model-config` projection, seeds the Experts registry, reconciles and starts the `ScheduleEvaluator`, and starts the `ExpertCompletionBridge`; a settlement orchestrator (when configured) follows `runtime.store.onCommitted` and sweeps at boot.
- [server.ts:startServer] — background loops: a live `follow: true` event stream tracking `workspace.added` into `knownWorkspaceIds` (aborted on `stop()`), and the observation drain `setInterval` (default 1000 ms, plus an immediate drain) from [observations.ts:wireObservations].
- [server.ts:startServer] — external processes (via the wired components): the pinned SXR CLI through the observation port's prerequisite workflow; `stop()` aborts the event follow, stops the evaluator/bridge/observation timer, stops the HTTP server, closes the runtime, and disposes every execution-world connection.
- [secrets.ts:secretStore] — filesystem: `readFile`/`writeFile` (mode 0600) + `chmod` of `secrets.json` under the home dir, `mkdir -p` of its parent; missing file reads as an empty map, any other read error propagates.
- [observations.ts:defaultSxrBin] — filesystem probes: `existsSync` on the configured `SXR_BIN` or the pinned `.tmp/realitytrace/bin/realitytrace` candidate.
- [observations.ts:observationOutboxFor] — commits one observation `OutboxIntent` atomically with each committed event whose type is in the module's `OBSERVED_EVENT_TYPES` set (the runtime's generic `outboxFor` hook); `observation.status`/`observation.record` read the delivery receipts and SXR correlation payloads.
- `import.meta.main` block of [server.ts:startServer] — environment reads: `PORT` (default 3180), `COGNATE_WORKBENCH_HOME` / `COGNATE_HARNESS_HOME` (default `<repo>/.data`), `COGNATE_DEV_AUTH`, `COGNATE_EXECUTION_POSTURE`; logs the listening URL, the auth posture, and the execution posture (a warning for `uncontained-local`).
